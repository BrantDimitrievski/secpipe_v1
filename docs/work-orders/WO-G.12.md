Implementation notes:
- Call cap: `propose()` loops while `attempts < MAX_ATTEMPTS`, but one `runner.run(...)` can itself use several calls, so the total can reach 5. `AgentRunner.run` has no budget today: add an overload `run(agent, input, grounding, maxCalls)` (1 ≤ maxCalls ≤ `MAX_ATTEMPTS`; the existing signature delegates with `MAX_ATTEMPTS`, so other callers are unchanged), and have `propose()` pass the remaining budget (`3 − calls spent so far`). The fresh re-run after a discarded result stays, but only within that budget. Test with a FakeLlmClient script of malformed and refused outputs and assert `llm.calls().size() <= 3` in every path.
- Strict context: keep fuzz 0. Accept a hunk at the line its header names when it matches there. Otherwise search after the previous hunk: exactly one exact match → accept at that offset; two or more → reject the whole patch with `hunk <n>: ambiguous context (matches at lines a, b, ...)`. Update the class Javadoc (it currently says "the nearest exact match wins").
- Prompts: rename `disprover.v1.txt` → `disprover.v1.md` and `testgen.v1.txt` → `testgen.v1.md` with `git mv`, then load them through `DefaultPromptRenderer` (template id unchanged: `disprover.v1`, `testgen.v1`). Keep the prompt **text** identical (the M.2/M.3 safe-API and follow-up guidance must survive). `DisproverAgent`/`TestGenAgent` `promptSha256()` must equal `DefaultPromptRenderer.sha256(<id>)`.
